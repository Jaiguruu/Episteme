**Built:** `maat/core/` (enums, locations, ids, contracts, serialization) and
`maat/offline/` (languages, snapshot, changes, parser, queries/*.scm,
extractors/, ir_builder, pipeline). 18 `.scm` extraction queries.

**Key design decisions (see plan D1–D22):**
- `ParserBackend` Protocol kept as the swappable parser seam (spec §10 deliverable).
- No language-specific shape crosses Tier 2 → Tier 3; Tier 3 sees only
  `SymbolFact` / `ImportFact` / `CallFact` / `InheritFact`.
- Three mechanisms let one engine serve 18 grammars: pairing by match
  (`@def.*` + `@name.*` in one pattern), nesting by span containment, and
  reclassification by context (function in class → METHOD).
- Content-addressed IDs (sha1 → 16 hex, `\x1f` separator). `model_version`
  excludes the parent so idempotent reindex does not mint a new version.
- Failure is data: `ParseStatus` OK/PARTIAL/FAILED/EMPTY/UNSUPPORTED, never raises.
- `SemanticIR` stores only the version **ID**, never the `ModelVersion` object —
  that is what keeps `ir.json` timestamp-free and byte-reproducible while
  `manifest.json` legitimately carries `taken_at`.
- M1 emits every reference as `UNRESOLVED` by design; resolution is M2.

`.scm` currently changes the model but not the version.

## MAAT / Episteme — MAJOR finding: bindings never reach the model

**`BindingFact` is produced but never consumed.** Grep of the whole `maat/` tree for
`bindings|BindingFact` returns hits ONLY in:
- `extractors/base.py` (the dataclass, the `ExtractionFacts.bindings` field, `to_dict`)
- `extractors/query_extractor.py` (where they are built and sorted)
- `offline/queries/*.scm` (the `@bind.*` captures)

There are **zero** hits in `ir_builder.py` or `pipeline.py`. Therefore:
1. `ir_builder.build_file_ir()` never reads `facts.bindings` — they are silently dropped
   at the Tier 3 boundary.
2. `SemanticIR` has no collection for bindings — nowhere to persist them.
3. `pipeline._group_by_file()` does not bucket bindings — incremental reuse would lose
   them even once they exist.

**Consequence:** bindings do NOT survive into `ir.json`. Confirmed by the live trace —
`ExtractionFacts` reported 4 bindings for `payment_service.py`, and `build_file_ir`
returned only symbols / relationships / evidence / chunks.

**This reshapes D23.** The M2 plan reads as "add `BindingFact` + `@bind.*` to the
extractor" — but that half is ALREADY DONE. What is missing is the consumption and
persistence path, which touches the persisted schema (`SemanticIR` needs a bindings
collection). M2 Stage 6 cannot resolve a single member call until this exists. Recorded
in TODO.md §4 (D23) and §6.

This is the single most important thing for anyone joining at M2.
